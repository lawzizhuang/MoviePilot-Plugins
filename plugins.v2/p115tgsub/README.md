# 115 TG 订阅追更（P115TGSub）

MoviePilot V2 插件：读取 MoviePilot 待处理订阅（状态 `N`、`R`），检索 Telegram 公开频道中的 **115 与夸克** 分享资源及 4K Monitor 匿名免费磁力候选，校验分享目录与缺集后转存缺失的电影和剧集；夸克转存成功后联动 SmartStrm 在本地增量生成 STRM。

## v2.4.14：Bot接收模式（当前行为）

开启Bot手动转存并设置用户白名单后，发送 `/tv <链接>` 或 `/movie <链接>`。命令仅选择配置的剧集／电影接收根目录，不调用TMDB、不要求片名语言或季集、不建立媒体子目录、不修改订阅。自动追更仍保留原严格身份校验。

- 115分享：只读取顶层项目，转存文件及文件夹并保留内部结构。单轮上限约束顶层项目数，不是内部视频数；文件夹内可能含大量或非视频文件，仅发送可信分享。
- 离线：标准ED2K文件链接与BTIH磁力直接提交到接收根目录，支持无dn的裸磁力。仍不支持BTMH-only、任意HTTP下载及种子文件。
- 保留协议检查、白名单、测试模式、互斥及目标路径失败保护。不再按媒体库或视频名称查重；整包成功后保存分享身份＋接收路径的哈希去重记录，离线按内容标识＋路径去重。
- 去重记录分别最多1000条，持久化保存、不自动到期或淘汰；分享内容更新仍会被同一记录拦截，重新导入需人工核查。部分成功或网络／状态保存异常无法保证严格一次执行，重发前核查115，避免重复。
- 旧版本离线记录按媒体子目录生成，与当前根目录键不同，不能保证阻止升级前任务重投。不要为验证升级而重发已下载资源。
- 必须让STRM监控及MoviePilot整理规则覆盖两个接收根目录；本插件不额外触发整理，不保证整理成功。识别失败留在接收目录人工处理。
- Bot预期错误返回具体的固定安全原因，不输出原始底层异常。TG与框架日志仍可能保留用户发送的链接，请使用受控私聊。

以下v2.4.12、v2.4.13段落为历史行为，媒体身份、季集、单媒体和dn限制已由本版取代。

## v2.4.13：Bot链接分流（历史）

`/tv`、`/movie`现在接受三类输入：HTTPS 115分享（原转存流程）、标准ED2K文件链接、包含`dn`名称参数的BTIH磁力（115离线提交）。一次仅一条，链接内空格须URL编码。裸磁力、BTMH-only磁力、HTTP直链和种子文件不支持；不能仅靠哈希安全识别媒体。离线名称须可靠匹配媒体，剧集须含明确季号。

离线提交复用现有剧集／电影根目录，不修改订阅；遵守手动转存开关、用户白名单和测试模式。Bot显式离线指令不依赖“自动追更离线兜底”开关。磁力内容提交前无法列文件，因此文件数量／实际季集无法预先核验，不将其视为已完成下载或已完成整理。首版离线查重为目标同名检查及内容标识＋目标路径哈希记录，不执行完整媒体库查重。

成功提交后仅持久化哈希，最多1000条，达到上限拒绝新提交，不自动淘汰或到期重投；失败任务的再次提交需人工核查记录。无自动离线完成轮询，下载及整理结果须在115与外部监控中确认。网络异常或保存状态失败可能造成提交状态不确定，请核查115后再操作，不能保证跨崩溃的严格一次提交。

## v2.4.12：Bot手动转存（历史）

开启“启用 /tv 与 /movie 手动转存”，填写允许调用的Bot用户ID（逗号或空格分隔，留空拒绝全部）。复用MoviePilot已配置Bot：

- `/tv <HTTPS 115分享链接>`：按剧集根目录／片名年份／Season N保存。
- `/movie <HTTPS 115分享链接>`：按电影根目录／片名年份保存。

首版只支持单部作品，链接访问码须包含在URL参数中；115分享转存不接受多部作品合集；磁力与ED2K自v2.4.13起走独立离线流程。视频数受单轮转存上限约束，目录深度最多3层，剧集必须有明确季集。遵守测试模式，不创建或修改订阅。与追更及进度核验互斥，忙时拒绝并提示重发，不另开并发队列。

转存完成后由已有STRM监控负责整理；本插件不额外触发整理，不把转存成功报告为整理成功。请使用受控私聊，链接会经过Telegram及MoviePilot命令处理链；本插件不在新增日志中输出链接，框架自身命令日志仍须注意保护。同名命令冲突与实机Bot响应需升级后小规模验收。支持文件名S01E01及Season 1、S01、第一季等目录季号（常见中文一至十）；不会擅自默认第一季。电影多个版本只取一个；合并多集文件若与已有集部分重叠则保守跳过，避免重复转存。首版只进行目标目录查重，未额外核验Emby，若文件已被整理移走，重发链接可能再次导入。

## v2.4.11：读取降压与失败保护

- 离线确认与正常查重复用同一份目标目录核验结果；子目录失败不再连带重读已完成的父级和兄弟目录。
- 目标目录每页最多1000项、最多20页，每页独立限速与有限重试；校验总数、偏移和条目标识，异常或超预算时暂缓，不用部分结果判断缺集。
- 路径查询失败不当作目录不存在，不以创建目录代替失败的存在性检查；网盘查重失败暂缓相关写入，运行汇总报告降级。
- 仅对明确取消／过期错误码4100010、4100018冷却六小时，最多512项，使用哈希键保存在客户端内存；重建客户端后清空，访问码变化隔离。405、超时等不缓存为失效分享。
- 不新增依赖或配置项，不修改Cookie或第三方插件；未包含HTTP级统一限流、跨轮405冷却及候选过滤，不宣称根治405。
- 升级后先启用测试模式核验少量订阅，再执行小规模正式任务。测试模式仍会读取网盘；发布前仅完成本地模拟回归，实机转存、整理及媒体库验收仍需确认。

## v2.4.10：私有本地资源表

在设置页开启“启用本地资源表”，填写容器内路径，例如：

```text
/config/resource_catalogs/影巢资源分享备份-20260905.xlsx
```

- 依赖 `openpyxl>=3.1.5,<4`，由插件依赖机制安装；只读 `分享明细` 工作表，不执行公式，不保存原表或输出凭据索引。
- 必需表头：标题、媒体标题、链接、访问码、备注、删除时间。排除已删除记录、公式字段、不支持链接；只导入115及夸克分享，不导入ED2K、磁力、其他网盘或分类视图。
- 精确规范化片名匹配，校验明确年份和季数；电影必须有匹配年份，最终仍依赖实际文件身份校验。表格没有可靠媒体类型列，不能单凭表内候选完成订阅。
- Telegram候选之后追加本地115候选，之后沿用现有离线流程；夸克兜底阶段追加本地夸克候选。每种网盘最多10个本地候选，与TG合并去重；不全量联网验活。
- 仅内存索引，文件大小或修改时间变化自动重新加载；读取失败时本次不使用旧表数据，其他来源继续。日志只显示计数、行号及异常类型。
- 默认关闭。首次开启请保持“测试模式”，验证候选及目录，不转存、不提交离线、不更新订阅。
- 更新时先上传临时文件，完成后替换正式文件；改文件名须同步修改配置路径。原表应位于私有持久化目录，不上传插件仓库或公开地址。

## v2.0 能力

### 115 链路（稳定保留）

- 仅访问 Telegram 公开搜索页 `https://t.me/s/<频道>?q=<片名>`，不支持私有频道、邀请链接或登录会话；
- 支持消息内直接的 115 链接，以及 `lsp115` 式「查看资源」跳转到 Telegraph 后的 115 链接；
- 仅接受 `115.com`、`115cdn.com`、`anxia.com` 域名分享；
- 自动处理全部 MoviePilot 待处理订阅；媒体库无缺集明细时按订阅声明范围回退；
- 单字剧名与标题过滤均保持严格匹配；Telegram 候选先按订阅标题初筛、再应用单频道上限；
- 115 的 STRM 生成与 302 播放由「115网盘STRM助手（P115StrmHelper）」链路负责，本插件不介入。

### 夸克链路（v2.0 新增，115 无可用候选时兜底）

```text
订阅缺失
→ Telegram / Telegraph 提取 pan.quark.cn 分享候选（与 115 同一次消息解析）
→ 解析分享 ID / 提取码
→ 运行时复用 QuarkDisk Cookie 获取 stoken
→ 校验分享目录与标题/季/集/扩展名
→ 115 无可用候选时，指定文件转存至夸克个人媒体目录
→ 异步任务等待 + 目标目录二次确认文件真实存在
→ 更新 MoviePilot 订阅缺集/note
→ 触发 SmartStrm 增量生成本地 STRM（失败进入待重试队列）
```

关键约束：

- **115 优先、夸克兜底**：同一集已由 115 链路成功转存（历史记录可见）时，夸克链路直接跳过，绝不双盘重复转存；
- 夸克 Cookie 仅运行时读取 `QuarkDisk` 的 `cookie` 配置，不复制到本插件、不回显、不写日志；
- 夸克远端只保存媒体文件；`.strm`、NFO、海报等全部由 SmartStrm 在本地生成，本插件不调用 MoviePilot 远端刮削；
- 提取码、`stoken`、`share_fid_token` 只在运行内存短期保存，不持久化；
- 风控词（频繁/风控/限制/封禁）触发冷却熔断，仅网络瞬态异常重试；
- 转存成功以「目标目录二次确认文件存在」为准，任务提交不算数；
- 转存成功与 STRM 后处理解耦：SmartStrm Webhook 失败只入待重试队列（最多 N 次后停滞告警），**绝不重新发起网盘转存**。

### SmartStrm 联动

- Webhook 地址从 SmartStrm「系统设置-Webhook」获取；本插件采用与 Quark-Auto-Save 相同的调用契约：
  - `GET webhook` 校验连通性；
  - `POST webhook`，`{"event": ..., "data": {"strmtask": "任务名", "savepath": "转存目标目录", "xlist_path_fix": ""}}`；
- `savepath` 只传本次转存成功的目标目录，SmartStrm 仅对该目录做增量 STRM 生成；
- 夸克网盘驱动时无需填写 `xlist_path_fix`；OpenList 驱动时填「挂载路径:夸克根目录」；
- Webhook 地址属敏感凭据：仅存于 MoviePilot 配置，不写入日志、通知或 Git。

## 部署与配置

1. 安装并启用「夸克网盘存储」（`QuarkDisk`）并完成 Cookie 配置（夸克链路运行时复用）；
2. 在「Telegram 公开频道」填写公开频道用户名或链接，每行一个（默认 `QukanMovie` / `lsp115` / `vip115hot`）；
3. 配置独立的 115 与夸克电影/电视剧转存目录；
4. 如需使用 ED2K / 磁力：在公开频道列表添加直链资源频道并启用「115 ED2K / 磁力离线下载」；4K Monitor 默认每轮按 TMDB ID 排查匿名免费候选；如需 SeedHub，另行启用「SeedHub 公开磁力资源」（默认频道 `seedhub_pro`）；
5. 配置夸克链路和 SmartStrm 后处理；
6. 保持「测试模式」开启，先点详情页「立即运行一次」，核对日志中的 Telegram、4K Monitor、SeedHub、115/夸克候选校验与剧集匹配；
7. 用详情页「验证夸克连通性」「测试 SmartStrm」分别做只读验证；
8. 确认无误后关闭测试模式。

## 操作页面

- **最近运行状态**：展示上一轮脱敏统计与最近媒体状态；不是实时执行进度。
- **订阅进度核验**：先点击“只读预览订阅进度差异”，刷新页面后通过统计卡片和差异表格核对每条订阅的 Emby 已入库集数、`note` 修复前后及缺失集数变化；确认无误后点击“确认按当前媒体库修复订阅进度”。该操作不会触发任何搜索、网盘或 STRM 动作。
- **立即运行一次**：异步执行一次完整同步（115 优先，夸克兜底）；
- **验证夸克连通性**：只读验证 `QuarkDisk.cookie` 与账号连通性；
- **测试 SmartStrm**：只读 GET Webhook 校验连通性，不触发任务；
- **清理插件日志**：清空本插件日志，不影响主日志与其他插件。

## 敏感信息边界

以下信息不会被本插件打印、记录或提交到仓库：115/夸克 Cookie、MoviePilot API Token、SmartStrm Webhook 完整 URL（日志仅显示主机名）、分享提取码、`stoken`、`share_fid_token`、完整分享 URL。下载历史仅记录分享 ID 与目标目录。
